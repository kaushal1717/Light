# Fleet v0.1.2

Date: 2026-09-28

## What changed

`fleet swarm` gains `--prompt-file <PATH>`: the worker's instructions are read from a file
instead of being pasted inline through `--prompt`. Supported formats are `.txt`, `.md`, and
`.pdf` (extension matched case-insensitively).

```sh
fleet swarm --repo . --task EUME-001 --role builder --agent claude \
  --prompt-file docs/plans/001_StnDailyDispatchCron.md
```

### User-visible behavior

- `.txt` / `.md` are sent to the worker verbatim (must be UTF-8).
- `.pdf` is reduced to its text layer with the pure-Rust `pdf-extract` crate; no external tool
  (poppler, etc.) is required.
- `--prompt-file` and `--prompt` are mutually exclusive (clap usage error, exit 2 — the same
  code as every other usage error in the CLI).
- The file is read before the repo is touched, so the instructions are resolved from the
  caller's working directory, not from the lane's worktree. An untracked plan file works.
- Refused with exit 7 and a message naming the path, never replaced by `--task`'s text:
  unsupported extension, missing/unreadable file, empty or all-whitespace text, non-UTF-8 text,
  a PDF with no text layer (e.g. a scan), a malformed PDF (parser errors *and* parser panics are
  both caught), a file over 16 MiB, or text over 256 KiB.
- The 256 KiB text cap exists because the prompt reaches the worker as one argv entry
  (`crates/builder/src/impl_/spawn/child_command.rs`) and macOS caps argv + environment at
  1 MiB (`ARG_MAX`).

### Fixed: a prompt starting with `-` never reached the worker

The parent passes the prompt to the `__agent` child as a positional argv entry. clap read a
leading `-` as a flag, so a prompt starting with YAML front matter (`---`) killed the child with
a usage error (exit 2) before it opened fd 3. The lane then ended `EnvironmentFault: agent
exited without an fd-3 result`, with no hint of the cause. This affected inline `--prompt` too,
but nearly every `.md` plan starts with `---`, so `--prompt-file` would hit it constantly. It was
found by running a real plan (`posx-eume-backend/docs/plans/001_StnDailyDispatchCron.md`).
`AgentArgs::task` now sets `allow_hyphen_values`, and the argv shape is unchanged.

- `src/Cargo.toml` — `pdf-extract = "0.12"`, version 0.1.2.
- `crates/cli/src/args_agent.rs` — `allow_hyphen_values` on the `__agent` task positional.
- `src/tests/swarm_prompt_front_matter/main.rs` — real-binary regression test (fails before the
  fix with exactly the EUME symptom).

## Known limitations

- Refusals raised by `swarm`'s argument validation (this flag, like the existing `--role` and
  `--task` refusals) exit 7 without writing a ledger receipt; AGENTS.md rule 8 is not met by
  any of them. Not changed here.
- Four files that were already over the 80-line cap grew by a few lines (`swarm_cmd.rs`,
  `args_core.rs`, `swarm_cmd_tests.rs`, `dispatch/mod.rs`). The over-cap count is unchanged
  from `main` (119); every new file is under 80 lines.
- PDF extraction quality depends on the PDF: multi-column layouts and tables can come out in a
  different reading order. Scanned PDFs are refused, not OCR'd.
- `cargo deny` is not installed on the machine that made this change, so the license policy was
  checked by listing `pdf-extract`'s dependency licenses against `deny.toml` by hand (all were
  on the allowlist; `r-efi` already has an exception), not by running the tool.
